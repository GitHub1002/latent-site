## 一、子 Agent 要隔离的是两样东西

多个 Agent 待在同一个运行时里。隔离做差了，子级一次读文件会改掉父级「这个文件我读到第几行」的记录，或者子级再派孙级，把 token 和任务表搞乱。

工具按身份过三道门：

1. 所有子 Agent 拿不到的工具：再派子 Agent、向用户提问、切换计划模式、停掉别人的任务。对话权和任务表留在主线程。
2. 用户自己写的 Agent 再严一层。它们没有经过内置角色那一轮约束。
3. 完全在后台跑、不能和人交互的 Agent 改用白名单：只允许事先点名的读、搜、命令和编辑。

MCP 工具在这道过滤里被放行，子 Agent 仍然够得着已经接上的外部系统。

上下文不能二选一。全部共享，子级读文件会污染父级的阅读缓存。全部新建，父级的取消信号传不进去，子级在你按下中断之后还在跑。实现按字段决定：

| 状态 | 处理 |
|------|------|
| 读过哪些文件、读到第几行 | 复制一份给子级 |
| 改全局界面状态 | 关掉，变成空操作 |
| 登记和结束后台进程 | 留一个小口，否则子级拉起的进程没人回收 |
| 身份 | 独立 id，嵌套深度加一，过深就停 |

信息怎么传、状态谁能写、哪条通路必须留、人在第几层，这四问各自有答案，而不是一句「隔离」带过。

## 二、Fork：为了让前缀一个字节都不变

内置的 Explore、Plan 带着自己的系统提示。每派一个，上万 token 的前缀都要重新算。提示缓存只在前缀字节级相同时命中。差一个空格、工具顺序变一下，缓存就失效。

Fork 派一个分身，让请求前缀和父级一致：系统提示、拼在前面的用户上下文（包括项目的 `CLAUDE.md`）、系统提示后面的环境信息、工具池的顺序和定义、对话历史里分叉点之前的那一段。这五项在实现里收成一组缓存安全参数。分身从父级的历史往下长，API 侧仍能认出那段前缀。

因此有两种派法。要一个工具更少、提示不同的专家，用普通子 Agent，接受缓存重新计算。要一个和父级看同一套说明书、只是从某一轮历史分开干活的分身，用 Fork。

## 三、Skill 是上下文的懒加载

五十个 Skill 若全文常驻，窗口会被手册占满。加载拆成三层：

1. **书脊。** 启动后只有名字和描述进清单，预算大约是窗口的百分之一，单条描述有字符上限。装得太多时，先缩短描述；再不够，第三方 Skill 只留名字。内置 Skill 的描述优先保留。
2. **正文。** 模型判断用得上，或你输入 `/名字`，才把 `SKILL.md` 读进来。它作为一条元消息插进对话，界面上不像用户又说了一句，模型却看得到整本手册。不改系统提示，是为了保住前面的提示缓存。改系统提示会让缓存整段失效。
3. **附录。** `reference.md` 和脚本仍不自动进入。正文写清路径，模型用 Read 自己打开。

斜杠命令和 Skill 是同一套命令。`/commit` 就是名为 commit 的 Skill。人可以点名，模型也可以在清单里自己对上。

选择不靠向量，也不靠一个小分类器。清单躺在上下文里，用户的句子也在，对得上哪一行描述，就是模型正在做的阅读。工具说明里把「匹配到就要先调用」写成硬要求，避免它嘴上提到 Skill、手上却直接干。描述是唯一广告位，含糊就等于没有这本书。

这和检索、记忆是同一条哲学：模型读得懂的事情，不再外挂一套会过期的索引。Skill 多到几百、描述被砍成只剩名字时，命中会下降。几十个的日常用量还在这套设计的舒适区里。

## 四、记忆是两层文件

静态层是你写的规矩，解决「我们怎么协作」。动态层是它在互动里写下的笔记，解决「我从你这里学到了什么」。两边都是 markdown，都进同一套加载，都不用向量库。

手写侧在 [01]({{< relref "claude-code-01-toolkit.md" >}}) 说过项目根那一份。加载时还会叠上这些来源：管理员托管的策略、用户主目录、项目、不提交的本地文件、自动记忆，以及可选的团队共享记忆。后两层常常是 `MEMORY.md` 而不是 `CLAUDE.md`，但它们和前面几层一起出现在系统提示里。`@路径` 用来引用一份共用规范。`.claude/rules/` 里带 `paths` 的规则，只有改到匹配文件时才注入。

动态层限制能写什么。只允许四类，其余不写：

| 类型 | 记什么 |
|------|--------|
| `user` | 你是谁。例如写了很多年 Go，刚开始碰前端。 |
| `feedback` | 你不喜欢什么、哪种做法被你确认过。正文要有规则、原因、何时适用。 |
| `project` | 项目里会过期的事实，例如某月某日开始冻结合并。相对日期要写成绝对日期。 |
| `reference` | 去哪里查。例如某类缺陷在某个工单项目里跟踪。 |

代码结构、文件路径、git 历史、已经进提交的修法、`CLAUDE.md` 里写过的话、当前这轮的临时状态，都不进记忆。代码是活的，一条写死的路径会变成一份权威的错误。只记从代码和 git 推不出来的事。

每条记忆是独立文件，头上有名字、一句话描述和类型。目录里的 `MEMORY.md` 是索引，常驻在系统提示里，所以同时限制行数和字节数。专栏提到过不到两百行、体积却很大的索引，只限行数挡不住。正文按描述按需打开，和 Skill 的书脊是同一种省法。

写入不放在主对话里做。主任务结束、模型不再调用工具时，一个后台抽取单独跑，决定有没有值得记的四类事实。主对话不必每轮都分神去想「要不要记下来」。

## 五、和本站已经读过的三份 Runtime 放在一起

| | Claude Code | Superagent | PocketPilot |
|--|-------------|------------|-------------|
| 循环 | 工具调用循环，有工具就继续 | Harness 上的路由会话加每张工单一个 Worker | 有界循环，Agent 不碰数据库 |
| 找代码 | Glob / Grep / Read，现读磁盘 | 工单目录里的 git worktree | 工作区里的读文件工具 |
| 记忆 | markdown 分层，索引常驻 | 工单、订阅和 Mandate | 工作区里有界的 `MEMORY.md` |
| 副作用 | 工具声明是否会改；Hook 和权限兜住 | Worker 以操作者的用户执行，包装不是安全边界 | 有副作用就停下来等人批 |

Claude Code 把「模型自己决定下一步」做到了产品里，再用文件、懒加载和隔离把窗口守住。Superagent 多了一层「什么时候允许开工」。PocketPilot 多了一层「改磁盘之前必须有人点头」。三份可以对照着读，它们守的边界不一样。

## 六、小结

- 子 Agent 的工具按黑名单和白名单裁剪。运行时状态按字段克隆、共享或关闭。
- Fork 让前缀和父级字节级相同，用来命中提示缓存。角色不同的专家用普通子 Agent。
- Skill 常驻书名，正文作为元消息按需插入，附录靠 Read。斜杠命令就是 Skill。
- 记忆只记代码推不出来的四类事实。索引常驻，正文按需打开，抽取放在主对话之外。
