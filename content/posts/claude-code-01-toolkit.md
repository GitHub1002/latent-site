本系列按 [图解 Claude Code](https://xiaolinnote.com/claudecode/)（小林面试笔记）的目录来学。实现细节来自该专栏对 Claude Code 的拆解，本站用自己的话重写，并接到已经读过的 Harness、Superagent 和 PocketPilot。

先有一张地图。专栏分五块：基础入门、实践技巧、源码解析、提示词、行业观察。本系列取能直接用、也能对着架构学的四篇：这篇讲六件套，[02]({{< relref "claude-code-02-query-loop.md" >}}) 讲主循环，[03]({{< relref "claude-code-03-context-search.md" >}}) 讲压缩和检索，[04]({{< relref "claude-code-04-agents-skills.md" >}}) 讲子 Agent、Skill 懒加载和记忆。提示词原文和行业观察留在原专栏，不在这里复述。

## 一、它实际在干什么

Claude Code 是 Anthropic 放在终端里的编程 Agent。你给一个目标，例如「修这个登录超时」。它自己决定先读哪个文件、再跑哪条命令、改哪几行，一轮一轮做下去，直到它认为可以停。

和补全式 Copilot 的差别在循环。补全是一次预测。Agent 是感知、决定、行动，再把行动的结果看一遍。决定下一步的是模型，应用层只负责把工具跑完、把结果塞回去。这件事 [02]({{< relref "claude-code-02-query-loop.md" >}}) 展开。

同一份 Claude Code，有人每次开新会话都要把技术栈再说一遍；有人打开就能按团队规矩审查 PR、格式化、把意见写回去。模型可以是同一个。拉开差距的是会话外面那套脚手架。

![六件套各管一件事](/images/claude-code-01-toolkit.svg)

| 你遇到的情况 | 用哪一件 |
|--------------|----------|
| 每次会话都要重说项目背景 | `CLAUDE.md` |
| 审查清单、发布步骤，用到才需要 | Skill |
| 搜索和日志把主对话灌满 | Subagent |
| 要碰到 GitHub、数据库、工单 | MCP |
| 规则必须每次都发生 | Hook |
| 这套配置要给同事、要换项目 | Plugin |

## 二、CLAUDE.md：每次都在的入职手册

模型没有跨会话的记忆。昨天那个会话关了，里面的话就没了。Claude Code 的做法很朴素：项目根放一份 `CLAUDE.md`，新会话把它放进上下文的前面。后面每一句话都站在这份文件上。

手写时常见三层：

- `~/.claude/CLAUDE.md`：个人偏好，所有项目都加载。例如回答用中文、提交说明写短。
- 项目根的 `CLAUDE.md`：这个仓库的技术栈和命令。启动就加载，适合签进 git。
- 子目录里的 `CLAUDE.md`：启动时不读。等到真的去动那个目录下的文件，才带进来。大仓库里 web 和 core 的规矩可以各写各的。

写的时候只留每次会话都用得上的句子。命令写成能直接执行的那一行，例如 `mvn test -pl web`，不要写「跑一下测试」。禁令写成「不许改」，不要写「尽量别动」。把架构文档整篇贴进去，每次会话都占窗口，真正的禁令会被稀释。`CLAUDE.md` 是工位上的一页手册，不是图书馆。

加载器实际拼进去的层级更多：管理员下发的托管策略、用户全局、项目、不进 git 的 `CLAUDE.local.md`，再加上自动记忆和可选的团队记忆。它们是叠在一起的，后写的不覆盖先写的。一份公司安全规范可以用 `@路径` 引进来，避免每个仓库复制一遍。`.claude/rules/` 里的规则还能带 `paths`，只有当前在改匹配的文件时才注入。这些按需规则，[04]({{< relref "claude-code-04-agents-skills.md" >}}) 和记忆放在一起讲。

## 三、Skill：用到才翻开的书

审查清单、发布步骤、改表规范，不是每次会话都用。塞进 `CLAUDE.md` 会白占窗口。Skill 把它们拆成两截。

一个 Skill 是一个目录，里面有 `SKILL.md`。文件头用 frontmatter 写 `name` 和一句话 `description`。启动时模型只看到所有 Skill 的名字和这句话。你说「看下这次改动」，描述对得上，它才把正文读进来。你也可以输入 `/code-review` 直接点名。

二十个 Skill 的常驻成本是二十句描述。每本正文可以有几千字，目录里还可以放参考文档和脚本。那些附件在正文被打开时仍然不进上下文，正文里写清「遇到表单再去读 `forms.md`」，模型用本来就有的读文件能力自己去拿。

`description` 是唯一的广告位。要写清「什么时候用」。写得含糊，这本 Skill 会一直躺在清单里没人翻。

## 四、Subagent：过程留在组员那里

让主对话自己做全仓库审查，每一次搜索、每一段文件、每一行命令输出都留在同一条上下文里。有用的往往是最后三行结论，过程把窗口灌满，前面写好的 `CLAUDE.md` 也被淹没。

Subagent 是派出去的组员。它在自己的上下文里搜、读、试错，干完只交结论。安全、性能、测试三件互不依赖的事可以同时派。配置放在 `.claude/agents/`，一份 markdown 一个角色。frontmatter 里写清何时用、允许哪些工具、用哪个模型。审查员只给 Read、Grep、Glob，不给写。翻日志这种体力活可以指定更快的模型。

正文最后写明交回什么。组员可以在自己的上下文里读很多文件，交回主对话的应是问题列表，而不是大段原文。

适合派出去的是过程重、结论轻、边界清楚的活。正在和你来回改的方案不要派。那边看不到这几轮讨论，还得把背景重新说一遍。

## 五、MCP：知识够不到的那些系统

模型可以写出调用 GitHub 的代码，却拉不下来第 128 号 PR。它有知识，没有一条真实通道。MCP（Model Context Protocol）是 Anthropic 定的插口：工具方实现一个 Server，声明自己有哪些工具、参数是什么；Claude Code 作为 Client 在需要时调用，把结果拿回来。

Server 可以是本机进程，走标准输入输出；也可以是远端 HTTP 服务。GitHub、Notion 一类官方集成走后者。

Skill 是说明书，MCP 是手。审查流程写在 Skill 里，真正去拉 PR、把评论写回去，靠 MCP。已经有好用命令行的事情，例如 `git` 和 `gh`，直接在终端里跑就行，不必再包一层 MCP。MCP 适合没有现成命令行、或者要保持登录态的系统。

## 六、Hook：提示词保证不了的那一次

`CLAUDE.md` 里写「改完要格式化」。十次里常常有八次照做。规则已经在上下文里，模型仍会漏。提示词是给模型看的文字，模型按概率遵守，没有机制保证每一次。

Hook 把命令挂在生命周期上：会话开始、你提交提示、工具调用之前、工具调用之后、准备结束回复。挂上之后由程序执行，不经过模型同不同意。

配置在 `settings.json`。`matcher` 筛选哪类工具，`command` 是要跑的命令。退出码 0 放行。退出码 2 拦住这次操作，并把报错交回模型，它会据此改做法。

两类最常用：

- 工具调用之后：改过文件就跑格式化。从此不必在 `CLAUDE.md` 里反复念叨。
- 工具调用之前：路径命中 `.env` 或密钥文件就以退出码 2 拒绝。模型收到「敏感文件禁止修改」，自己换方案。

## 七、Plugin：把散装配置收成一个盒子

六件套配齐之后，文件散在项目各处。换仓库要手抄，同事抄到的是你两周前的版本。Plugin 不增加新能力。它把 Skills、Subagents、Hooks、MCP 配置收进一个目录，用 `plugin.json` 写名字和版本，通过 marketplace 分发。marketplace 可以就是一个 git 仓库。同事一条安装命令拿到同一套审查能力，你发新版本，他更新一次就对齐。

Hook 能在机器上执行命令，MCP 能连外部服务。装来源不明的 Plugin，和插入来路不明的可执行文件是同一类风险。团队仓库和你审过的开源项目再用。

## 八、一次审查里它们怎么同时出现

会话一开，`CLAUDE.md` 已经在。你说「审一下今天这个 PR」。

MCP 把 PR 的改动拉下来。审查派给 code-reviewer，它在自己的上下文里按 code-review 这份 Skill 逐个文件看。主对话只收到结论。接着改代码，每次写入后 Hook 跑格式化；它若去碰密钥文件，调用前的 Hook 拦住。意见再经 MCP 写回 PR。

这套文件可以都装在同一个 Plugin 里。少一件，这条链路就会在某一处靠模型自觉，而自觉不稳定。

## 九、小结

- Claude Code 的循环让模型自己决定下一步。六件套决定这件事能不能稳定发生。
- `CLAUDE.md` 每次都在，只写每次都用得上的规矩。专项流程做成 Skill，用时再打开。
- 过程重的活派给 Subagent。外部系统走 MCP。必须发生的动作写成 Hook。Plugin 负责把它们带走。
