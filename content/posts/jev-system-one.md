2026 年 9 月 15 日，TypeSafe AI 放出第一个 **System One** 模型 [Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev)。名字借 Kahneman 的快思考，也借 Jevons：智能变便宜之后，调用次数会涨，而不是缩。创始人 Diogo Almeida 是 ChatGPT 背后那套 RLHF 的共同发明人之一——他现在卖的东西，故意**不再会说话**。

一句话定位：

> Jev 是给软件调用的决策函数：非结构化状态进去，你事先写死的选项、量表、是否题出来。它不写回复、不写代码、不解释自己。

本站前面把 Agent 写成「循环 + 工具 + 策略」。Jev 不进那三份源码样本；它回答的是另一问：**循环里总有几步，条件在数据库里找不到，关键词规则又太脆，你又不想为了这一个判断跑一遍会写长文的大模型。**

## 一、同一条消息，三种东西分别干什么

用户说：

> 我订的机票被取消了，明早就得走，马上帮我改签，不然我投诉。

**大模型**会接着写。你可能得到一段安抚，或一段计划：查订单 → 搜航班 → 调改签接口。输出是给人读的，或者还要再解析才能进代码。它擅长开放空间：生成、解释、多步推理、填工具参数。

**工作流**是你已经想清楚的固定图：订单状态是取消、起飞不足 24 小时、金额大于 500 就审批。准，是因为规则是人写死的，输入也是库里的字段。可是「很急」「像要改签」「可能投诉」在表里没有布尔列。

**Jev** 不写那段话，也不替代那张图。你传的不是「请回复客户」，而是状态 + 一组事先定义的问题：

```json
{
  "model": "jev-latest",
  "state": "我订的机票被取消了，明早就得走，马上帮我改签，不然我投诉。",
  "questions": {
    "queue": {
      "type": "choice",
      "instructions": "分到哪个队？",
      "criteria": {
        "billing": "退款、扣费",
        "rebook": "改签、航班变动",
        "complaint": "投诉、升级"
      }
    },
    "urgency": {
      "type": "score",
      "instructions": "紧急程度",
      "criteria": ["可以等几天", "今天处理", "立刻处理"]
    },
    "escalate": {
      "type": "noul",
      "instructions": "要不要马上转人工？"
    }
  }
}
```

回来是这种东西（示意，不是一次真实调用的日志）：

```json
{
  "queue": {
    "type": "choice",
    "choice": "rebook",
    "probabilities": { "billing": 0.02, "rebook": 0.91, "complaint": 0.07 }
  },
  "urgency": { "type": "score", "score": 1.8 },
  "escalate": { "type": "noul", "noul": 0.86 }
}
```

代码直接用：

```python
if answers["escalate"]["noul"] >= 0.8:
    handoff_to_human()
elif answers["queue"]["choice"] == "rebook":
    start_rebook_workflow()
```

没有客服话术，也选不了你没列的第四个队列。生成仍交给大模型；分支仍交给工作流。

## 二、三个原语：Choice、Score、Noul

官方 API 是一次 `POST https://api.typesafe.ai/v1/systemone`。同一份 `state` 上可以挂多道题，并行出结果。题只有三种：

| 原语 | 你在问 | 它返回 | 代码里怎么用 |
|------|--------|--------|--------------|
| **Choice** | 在给定标签里选一个 | 获胜键、每项概率、confidence | `switch` / 路由 |
| **Score** | 落在你写的有序量表上 | 概率加权分数（可落在两档之间）、分布 | 阈值 |
| **Noul** | 是不是 | 0–1 的「是」的概率；没有单独的 confidence 字段 | `if p >= θ` |

选型规则很土，也够用：答案能直接驱动哪一种控制流，就用哪一种。三个都能绕着写成 Choice，但会逼你在代码里再翻译一层。

Noul 这个词官方没展开词源，当专有名即可。Choice 最多 255 个选项；Score 的量表是 2–10 档。当前公开别名是 `jev-1.13.0` / `jev-latest`。

## 三、和大模型差在哪

差在**产出什么**，以及**为谁服务**，不在「谁更聪明」。

| | 大模型（LLM） | Jev |
|---|---|---|
| 训练目标 | 生成下一个 token；偏慢思考（System Two） | 校准过的决策（他们叫 RLCD） |
| 输入 | 对话、长上下文 | 程序状态 + 你定义的问题 |
| 输出 | 文本、代码、解释；格式还要解析 | 只能是你定义的三种值 |
| 幻觉面 | 可能编格式、编不存在的选项 | 选不了没列的选项，也写不出散文 |
| 调用方 | 人读，或 Agent 再解析 | 代码直接消费 |
| 速度 / 成本 | 秒级常见；输入输出都计费 | 厂商自称约 70–500ms；输入 $0.042/MTok，输出免费 |

「不能幻觉」要听窄：**格式和类型**由请求形状钉死，语义照样可能判错。把投诉判成退款、把反话判成同意，仍然可能发生——只是它不会发明一个叫 `vip-channel` 的第四队列，也不会在 JSON 外再写一段「另外我建议你……」。

大模型用 JSON mode / tool call 也能吐结构化结果。那是在生成管道上套约束；Jev 是把生成这条路关掉，换并行采样和（他们声称的）校准概率。你为结构化输出付的税，从「解析 + 重试 + 校验」变成「事先写死答案空间」。

## 四、和工作流差在哪，为什么还要用

工作流更准——当条件已经是字段的时候。`order.status == cancelled and hours_to_departure < 24` 不需要模型。

Jev 填的是工作流**写不出 `if` 的那一格**：输入是自然语言、日志、邮件、工具结果，判断是「像不像要升级」。它不替代流水线，只当传感器：

```
一段话
  → Jev：队列=改签, 紧急度=1.8, 转人工=0.86
  → 工作流：if noul >= 0.8 → 转人工
           else → 改签子流程（查订单、搜航班、写确认）
  → 大模型：生成给改签工具的参数，或写给用户的那句安抚
```

左边模糊，中间固定，右边开放。三层叠在一起才是产品；单独把 Jev 当成「又一个流程引擎」会用错。

所以该用哪个，看卡在哪：

| 情况 | 用什么 |
|------|--------|
| 订单状态、金额、时限都在库里 | 工作流 / 规则，别上模型 |
| 要从一段话里判断意图、情绪、风险 | Jev，或大模型做分类 |
| 判完还要改签、写回复、调 API | 工作流 + 大模型 |
| 需要解释给人或生成代码 | 大模型，Jev 做不到 |

Jev 有用，不是因为它比工作流更准，而是因为真实系统里总有几步的条件写不成 `if`，而你又不想为了这一个判断去跑一遍会写长文的模型。

## 五、放进 Agent 里，它站哪

本站 [PocketPilot]({{< relref "pocketpilot-03-policy.md" >}}) 的策略层认的是 capability 后缀和路径牢笼：未知能力不注册，绝对路径进不了 `open()`。那是**硬规则**，不该换成模型。

Jev 适合站在硬规则前面或旁边，处理规则吃不下的模糊门：

- 这条用户消息要不要升级审批，而不是只看工具名
- 模型刚生成的 tool call，语义上像不像越权（规则已经拦住了路径逃逸）
- 多工具候选时先做一次路由，再把选定的工具交给大模型填参
- 对 LLM 的输出做一次「像不像注入 / 像不像要外泄」的打分，再决定放行

[系列一的安全篇]({{< relref "stage5-18-safety-guardrails.md" >}}) 讲过输入过滤和输出验证。Jev 可以把其中「像不像攻击」收成一道 Noul，阈值仍由你定。它替代不了 WorkspaceGuard，也替代不了人工审批；它替代的是你现在用大模型硬做的 JSON 分类。

Function Calling 仍然是大模型的活：选工具、填参数。Jev 不调 API，只告诉工作流「现在该走哪条边」。

## 六、厂商说法听到哪

公开材料里还有这些，建议当**厂商自称**，不要写进自己的架构承诺：

- 端到端 70–500ms，相对前沿 LLM 大约 40–200 倍；工作流评测页上出现过更高的倍数，官方自己说那是偏乐观的一端
- 输入 $0.042 / MTok，输出免费；他们也写了无法证明没有补贴
- 架构、并行采样器、RLCD 的细节未发表；「不是小 LLM」是宣传口径，外部还不能独立核实
- 评测用自家 System One 封装去约束别的 LLM，再拿 Astra / Fable 的平均当参考——比的是「封闭决策任务」，不是聊天、写代码、长推理
- 目前是 early access；输入以文本状态为主

听得进的部分其实更窄：它把产品形状收成「软件可依赖的决策接口」，并且承认自己放弃了字符串。这对 Agent 工程有用。听成「又一个更强的通用模型」或「工作流可以退休」，就会用错地方。

## 七、什么时候不要用

- 条件已经在数据库里：写 `if`。
- 需要一段给人读的话、一篇代码、一条多步计划：用大模型。
- 答案空间你自己都写不出来：先把标签设计清楚，再考虑模型。
- 决策一旦错了不可逆、也没有阈值和人工兜底：不要把概率直接当动作。
- 你只是想少写 JSON schema：大模型加约束输出往往够用，不必为了「新模型」改架构。

Jev 值得写进本站，不是因为它会取代系列一里的 LLM 课，而是因为它把一个一直被混在「让大模型 json 一下」里的职责拆出来了：**开放生成、封闭决策、固定流程，本来就不是同一件事。**
